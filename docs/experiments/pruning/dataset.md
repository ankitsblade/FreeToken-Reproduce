# Pruning datasets and evaluation scope

This page distinguishes the original routing corpus from the fresh actual-inference corpus. All three qualified checkpoints use the same task text within a study, with checkpoint-specific tokenization and templates.

## 1. Original static routing study

- 90 primary requests per checkpoint: 30 math, 30 code, 30 incident.
- Five global grouped folds, seed `20261006`. Related request groups are assigned together. Each held-out request is excluded from its calibration fold.
- Separate 15-request pilot, five per workload.
- Nine preselected repeat requests, three per workload, captured two additional times: 18 additional captures/model. Repeats are sensitivity measurements, not additional independent tasks.
- Four calibration pools: math, code, incident and mixed; prefill and decode analysed separately.
- Recorded access/gate coverage, oracle/random controls, layers/windows, transfer and stability. This routing corpus has no task-quality answer rubric.

The early standalone bandwidth experiments also used `experiments/prompts/routing_workloads.jsonl` and locally cached AIME material in selected runs. Those fixtures do not describe the later 300-task quality corpus or qualify the full static collection.

## 2. Actual 75% inference corpus

Locally authored synthetic tasks, generated by [build_pruning_quality.py](../../../experiments/pruning/build_pruning_quality.py) and frozen under `results/moe_pruning/study_20261006_v1/additional/actual_masking75_v6/quality_corpus/`.

| Workload | Prompts | Families | Variants/family | Content and scorer |
|---|---:|---:|---:|---|
| Math | 100 | 10 | 10 | Arithmetic, algebra, progressions, probability, geometry, combinatorics; exact rational final answer |
| Code | 100 | 10 | 10 | Small Python pure functions; all 8-9 frozen cases must pass, including input-mutation checks |
| Incident | 100 | 10 | 10 | Operational scenarios; correct action contributes 0.6 and two expected evidence substrings contribute 0.2 each |

All 300 prompt hashes are distinct. Substantive tasks are less diverse: incident variants predominantly change identifiers; some code variants only change the required function name. This is not 100 independent problem families/workload.

### Calibration and evaluation separation

Deployment masks are fitted after the offline closeout from the original 90 calibration-design routing requests: all 90 for mixed and 30 for each task-specific mask. Exact prompt overlap with the 300 new quality prompts is rejected. Shared concepts across these corpora are not thereby excluded.

There is no model training/fine-tuning split. The 300 prompts are the evaluation set. They run under baseline, mixed75 and their own task-specific75 mask. Across three models, this produces 2,700 task generations.

### Twelve execution shards

Task/sequence ordinal modulo 12 assigns each item exactly once to a frozen fresh-process shard. Each shard contains 25 tasks, eight or nine/domain, and eight or nine text sequences. All treatments for an item remain in the same shard. These are resource-management partitions, not cross-validation folds or independent test datasets.

### Generation and output handling

- Greedy, natural EOS, maximum 256 generated tokens.
- Qwen/Gemma thinking disabled; GPT-OSS low reasoning effort. These settings differ from the original thinking-enabled routing-capture arm.
- Save final content, reasoning content, token counts, finish reason and failures.
- Grade the final submitted answer. Invalid/missing structured output and functional failures can score zero. Truncations are recorded and unfinished answers can fail.
- The incident rubric uses substrings and can miss valid paraphrases or credit weak explanations containing expected terms. Code cases are finite, and the restricted worker is not a general security sandbox.

## 3. Fixed-input likelihood corpus

- 100 authored operational narrative sequences from ten templates, expanded through repeated paragraphs with changed numbers/identifiers.
- Checkpoint-specific 320-token causal input: 64-token prefix, then 256 scored continuation tokens.
- Baseline, all100 identity control and four 75% masks: 600 likelihood calls/model, 1,800 overall; 25,600 scored continuation tokens per mask/model.
- Compare NLL/perplexity, full-vocabulary KL and token agreement within each checkpoint/tokenizer. Raw perplexities cannot rank models with different tokenizers.
- Likelihood is evaluated on fixed text through native prefill; autoregressive task evaluation propagates changed activations and token histories.

## 4. Statistics and quality decisions

Frozen margins: two percentage points task-score loss and 2% relative perplexity increase. Decisions use upper 95% paired bootstrap bounds, with unsafe-choice increases blocking serving qualification. Wide intervals remain inconclusive.

Resampling units are the ten task-template families/domain and ten reference-text clusters. It is invalid to treat all parameter variants as independent problem families. A zero loss on a baseline that already fails is not useful task preservation.

The combined synthetic screen passed for GPT-OSS math/code and Qwen code. Qwen mixed math dropped from 72% to 42%, even while its mixed-mask reference-text perplexity decreased about 2.21%. Lower authored-text perplexity therefore does not imply better task answers.

## 5. Scope relative to the original plan and paper

The original requirement for at least 100 independent quality tasks/workload is **unmet**. The completed actual75 stage is an exploratory synthetic supplement, and its passing decisions do not establish broad real-world quality preservation.

This corpus is not the FreeToken paper's evaluation dataset. The archived paper's Section 5.1 describes AIME reasoning, a SWE-bench issue through OpenCode and Claude Code, and fixed email/calendar turns through OpenClaw. The paper preserves exact routed computation; the pruning supplement introduces an additional quality question. See [the archived paper](../../references/2608.16157v1.pdf).
